# Talaan: Frontend reference

Moved from CLAUDE.md on 2026-11-16. The every-session rules are repeated as one-liners in CLAUDE.md.

Next.js (App Router, TypeScript, Tailwind v4, npm) in `frontend/`; deploys to Vercel later (root directory `frontend`). Source of truth for look: `docs/DESIGN.md`; PNGs in `docs/design/` are visual references only.
- Commands (run in `frontend/`): `npm run dev`, `npm run lint`, `npm run typecheck`, `npm test` (Vitest), `npm run build`. Node 24.
- Layout: `src/styles/tokens.css` (all colors, radii, type, shadow as a Tailwind `@theme static` block), `src/app/` (routes, `globals.css`, `icon.svg`), `src/components/`, `src/lib/`, `tests/`.
- Rules: tokens only; no hex outside `tokens.css` (and `app/icon.svg`, enforced by `tests/no-hex.test.ts`); dark mode comes from the variables (`light-dark()` + `color-scheme`), never `dark:` variants; sentence case, no `uppercase`; IBM Plex Sans only (400/500/600), no mono or serif; no component library, CSS-in-JS or animation library; no new dependencies without asking.
- Forms: every form uses `noValidate` and shows our own inline errors; no native validation popups.
- Theme: "system" default, override saved in `localStorage` (`theme` = `light` | `dark`), applied by an inline script in `<head>` before paint.
- Next.js here is newer than common training data; check `frontend/node_modules/next/dist/docs/` before using an unfamiliar API. `agentRules: false` stops `next dev` re-creating `frontend/AGENTS.md`.
- Changing a token: `npm test` runs the WCAG contrast checks from DESIGN.md and fails below the ratio.
- Components (`src/components/`, all shown on `/design` in both themes): `Icon`, `Button` (primary/secondary/ghost/destructive; `href` renders a link), `TextField`, `PasswordField`, `Textarea`, `Select` (`fields.tsx`), `SegmentedControl`, `StatusStamp` (+ `STATUSES`, `OUTCOMES`, `stampLabel`), `StatusFilter` (`status-filter.tsx`: the list's native Status select, replaced the filter tabs), `WakingUp` (`waking-up.tsx`: "Starting up..." polite line after 3 s of a pending request; on the applications screen only before anything has loaded (`loadedOnce`), one copy above `<main>` below 1280 and one inside the h-dvh list pane from 1280), `Banner`, `Logo`, `LogoLink` (`logo.tsx`: the app bar and side nav logo, one link to `/applications`), `ThemeToggle`, `LedgerSheet`, `ApplicationRow`, `InterviewRow`, `DetailRows`, `LedgerSkeleton` (`ledger.tsx`), `Dialog`, `DeleteConfirm`, `StatusDialog` (`dialog.tsx`; radio group + "Update status"), `ToastProvider`/`useToast` (`toast.tsx`), `EmptyState`, `NotFoundState` (own title/link props), `ApplicationForm`, `InterviewForm`, `AgendaRow` and `InterviewMeta` (`ledger.tsx`), `AddToCalendar` and `CalendarGuide` (`calendar.tsx`; the guide is a `Dialog` with `focusTitle`; `available` hides only its trigger, an open guide stays open, `onGone` takes focus on close once the trigger is gone; toast "Calendar file created."), `TextAction` (`button.tsx`: the one 44px text action, tones bar/primary/danger; `BarAction` wraps it). `SegmentedControl` takes `value: null` (nothing chosen), `required`, `error`.
- `TextAction` `external` (with `href`): a plain `<a>` to another site, opened in a new tab (`rel="noopener noreferrer"`); `disabled` is ignored: the link always looks and works enabled. Visually hidden "(opens in a new tab)" text is appended to its name.
- Lib: `ics.ts` (`buildIcs(item, {now, origin})` -> text or null, `icsFileName`: pure, UTC start from the stored instant, end +1 h, CRLF, fold 75 octets, UID `talaan-interview-<id>@talaan`, never reads notes), `getAgenda(when, offset, asOf?)` in `api.ts` (page 1 omits `asOf`, the server echoes `as_of`; every Load more sends it back, URL-encoded; the agenda cache entry keeps `asOf`), `groupByPhtDay`/`isUpcoming` in `interviews.ts`, `formatDayHeading` in `format.ts`. The agenda cache (`cache.ts`: `getAgenda`/`setAgenda`/`agendaVersion`) is dropped by `clearCaches` and by `clearDetail`/`replaceDetail` (so by every interview and application write and every auth event) and kept by `storeApplication`. `src/lib/types.ts` (API field names: `job_name`, `remarks`, `contact_website`, `mode_of_work`, `scheduled_at`; mode labels and icons via `WORK_MODES`/`INTERVIEW_MODES`, `workModeLabel`, `interviewMode`), `format.ts` (`formatPeso`, `formatDate`, `formatDateTimePHT`, `dateAppliedLabel`; all return null on missing/invalid input, dates always Asia/Manila, date-only strings stay calendar dates), `interviews.ts` (`sortInterviewsByDate`), `pht.ts` (`toPhtInput`, `fromPhtInput`, `phtYearOk`: interview times are Philippine time only, never the browser zone; UTC getters and string rebuilding only), `interview-form.ts` (pure validation, like `application-form.ts`), `use-leave-guard.ts` (`useLeaveGuard`: the one `beforeunload` guard). `api.ts` is the real applications client (all through `request()`): `getApplications(status?, offset?)` -> `{items,total}` (50 per page; the API caps a page at 100 and filters by `status`), `getApplication(id)` (null on 404), `getInterviews(id)` (`limit=100`), `getInterview(id)` (null on 404), `createInterview(appId, input)`, `updateInterview(id, initial, next)`, `deleteInterview(id)` (`updateInterview(appId, id, ...)` and `deleteInterview(appId, id)` take the parent id for the scoped clear; the backend PATCH/DELETE are flat `/interviews/{id}`; same write rules as the application writes: `clearCaches()` first, id-only result, 404 on delete = success), `createApplication`, `updateApplication(id, initial, next)` (PATCH with only changed fields; both resolve to the row's id only and clear the caches before reading the response), `deleteApplication` (404 = success), plus `parseId`, `parseStatus`, `parseFilter`. Cache rules (`cache.ts`: in-memory per-tab list cache and detail cache, never web storage; each operation sets the new state before notifying, in one synchronous step): application create, edit and delete call `clearCaches()` (also any 404 on a write and a status PATCH with no answer: status 0 or a gateway 502/503/504); login, logout and account deletion call `resetCaches()` (`clearCaches()` plus the end of every status window, since a PATCH answered 401 never settles); `changeStatus(id, status, from)` (resolves to nothing) calls `storeApplication(row, from)`, which patches every cached list from its own rows (`patchList`: replace in `all`; a status list holding the row under another status loses it, `total`/`nextOffset` - 1; the new status inserts it at its `created_at desc, id desc` place inside the held rows or into a complete list; a list whose result cannot be known (row beyond the cursor of an incomplete list, or unknown order) is dropped) and the detail from the server's row, with no refetch (an unmappable response, a 404 or no answer, including the 60 s `STATUS_TIMEOUT_MS`, falls back to `clearCaches()`; a 2xx whose body read the timeout cut off (`ApiError.httpOk`) counts as saved: clear and resolve). List epoch: `beginMove()`/`endMove()` bracket the PATCH; a list response is stored only if `listFresh(stamp)` (stamp unchanged since `clearCaches`/`storeApplication`, no status write in flight), else it waits for `listsSettled()` and is re-issued (page 1 restarts, Load more retries once); `use-detail` guards its application request with a local counter bumped on a status change (not `detailStamp`, which would drop a valid interviews request) (DECISIONS.md 2026-11-10); interview create and edit call `clearDetail(applicationId)`; interview delete calls `replaceDetail(applicationId, page minus the row)` (the detail still refetches); an interview changes no list field, so the list cache and in-flight list responses survive, except the follow-up list (key `follow_up`, `getApplications("follow_up")`, rows carry `follow_up: {idle_days, last_activity}`): it is marked stale (`listStale`), never patched, because who is on it depends on interview times and the clock. A stale list is kept, so the screen shows its rows while `use-list` refetches page 1; `setList` (a stored server answer) clears the mark, and Load more on a stale list asks for page 1 instead of appending. `storeApplication` marks it before patching the others, `clearDetail`/`replaceDetail` mark it and move the list epoch (so a follow-up page requested before is refused and asked again, as is one normal-list page in flight), `clearCaches`/`resetCaches` drop it with the rest. `parseFilter` (a status or `follow_up`) replaces `parseStatus` at the `?status=` sites, so back, cancel and redirect links keep the follow-up view; it is never used as a status value. `loadedOnce()` (set by the first stored list or detail, never reset) gates the waking-up line. `mappers.ts` is the only place that knows the JSON shapes (unknown enum -> `MappingError`; date-only strings untouched; request bodies list fields by name so `contact_email` is never sent) and holds the form <-> API conversions. `application-form.ts`: pure validation mirroring the backend (limits counted in code points, `maxLength` 2x as a typing cap), dirty check, 422 mapping. Components import `../lib/...` relatively; Vitest now has an `@` alias (only app screens use `@`).
- Dialog: native `<dialog>` + `showModal()`; `open` prop is the truth, parent clears it in `onClose`; no scrim-click close; `data-autofocus` picks initial focus; `onClose` fires only for user closes; `DeleteConfirm` `busy` disables both buttons and Escape, and re-opens after a native close. Toast: two always-mounted live regions, success 4s (pauses on mouse hover/focus, not touch), max 3 per kind; dismissing the focused toast moves focus to the next toast or back to where it came from. jsdom has no `showModal`; `tests/setup.ts` stubs open/close/Escape only (not inert or focus trap).
- Component rules: every control at least 44 x 44 (a 36px DESIGN visual sits inside a 44px hit area, focus ring on the visual); fields draw a 2px primary ring over the border (6.2), everything else uses the global `:focus-visible` ring in `@layer base`; fields forward `ref` and native props; status/outcome values must equal the API enums (tested against `app/*/models.py`); icons are inline SVG paths in `icon.tsx` (no icon font); transitions at most 100ms. Tests: RTL + user-event, DOM tests start with `// @vitest-environment jsdom`.

- Routes: `/interviews?view=month` (F9: `?month=YYYY-MM` invalid or missing -> current PHT month via replace, `?day=YYYY-MM-DD` outside the visible grid -> today if in the month else the 1st; the View switch, header and import guide stay mounted, `AgendaScreen` picks `AgendaBody` or `MonthView`; Month is 640 wide, 960 from 1280; grid in `components/month-grid.tsx`, data in `use-calendar.ts`, math in `lib/calendar.ts` (pure, UTC getters, 1900-2200), `getCalendarRange(from, to)` in `api.ts` and `getCalendar`/`setCalendar` in `cache.ts` share the agenda's clear rules and `agendaVersion()`; local e2e `scripts/e2e-calendar.cjs`, shots `scripts/screens-calendar.cjs` into `.screenshots/f9/`; works with Playwright 1.64.1 + chromium build 1243). `/interviews` (F8 agenda: Upcoming / Past in `?when=past`, `GET /interviews?as_of=` pins the split across pages, a tab switch is a new request generation, Load more busy per tab, PHT day groups, rows link to `/applications/{job_application_id}`, Load more 50, `use-agenda.ts`); `/` redirects to `/applications`; `/login` (wired; `?expired=1`, `?deleted=1`, `?next=`); `/privacy` (public static page outside the shell, no API call; in `PUBLIC` in `proxy.ts`; linked from the login/signup screen and Account); `(app)` group with the shell (`MainNav` bottom bar under 768, 88px rail from 768, 240px ink side nav from 1280, skip link, `ToastProvider`; toasts clear the bottom nav via `--bottom-nav`); `/applications` and `/applications/[id]` share `(ledger)/screen.tsx` (separate screens under 1280, list + detail panes from 1280, list pane scrolls on its own so selecting a row keeps its scroll); `/applications/[id]/interviews/new` and `.../[interviewId]/edit` (full-screen `InterviewForm` in the shell, outside `(ledger)`; time field "Date and time (Philippine time)", mode required with nothing chosen, outcome default Pending, saving never changes the application status; edit always fetches fresh and treats an interview of another application as not found); `/account` (real user, theme, log out, Privacy link and Send feedback link (external TextAction; `FEEDBACK_URL` lives in `account-screen.tsx`, and `account.test.tsx` and `e2e-auth.cjs` hard-code the same URL), two-step delete); `/admin` (A1: `(app)/admin/admin-screen.tsx`, calls in `lib/admin.ts` (`listInvites`, `createInvite`, `revokeInvite`, all through `request`); the new code lives in component state only, never in a cache or storage; a 404 from the list renders `notFound()` inside the shell; linked from Account only when `user.is_admin`, not a nav item; local e2e `scripts/e2e-admin.cjs`); `/applications/new` and `/applications/[id]/edit` are noindex pages sharing `ApplicationForm` (work mode starts unselected on create; status defaults to Saved; Cancel and the back arrow ask "Discard changes?" only when dirty; `beforeunload` registered only while dirty; the browser Back button and side/bottom nav links are NOT intercepted; success = toast + `router.replace` to the detail keeping `?status=`). Edit always fetches the record fresh. The list is `use-list.ts` (per-status cache, stale-while-revalidate, Load more from `nextOffset` with de-dup (a page with no new row withdraws Load more and refetches page 1), announces "N more applications loaded" in the screen's persistent `role="status"` region (cleared after 5s, on tab switch and on detail change) and moves focus to the first new row); the detail is `use-detail.ts` (a clear shows the skeleton, never pre-write data; the exceptions are an interview deleted in place (`replaceDetail` swaps in the page minus that row in the same step as the clear, so the render takes the cached path and the background refetch replaces it) and a status changed in place (`storeApplication` hands the detail the server's row as its fresh application: no skeleton, no refetch, actions stay enabled; the list pane keeps its rows, loaded pages and scroll) (DECISIONS.md 2026-11-09); after a delete, focus goes to the Interviews heading, or to Add interview when none remain; application and interviews fail separately; cached detail shows with Edit/Delete disabled and `aria-busy` until fresh; a 404 evicts the id from the cache). List and detail responses whose request started before a `clearCaches()` are dropped (`cacheVersion`). A 401 redirect sets `isLeavingForLogin()` so `beforeunload` guards stay quiet. `ThemeSync` in the root layout does cross-tab theme sync. `AppBar` is hidden from 1280.
- Auth wiring (F4): the browser only calls `/api/...` on the Next origin; `src/proxy.ts` rewrites it to `BACKEND_URL` (`frontend/.env.example`, default `http://localhost:8000`, set in Vercel; read per request) and, with `PROXY_SECRET`, adds `X-Talaan-Client-IP` (from `x-real-ip`) and `X-Talaan-Proxy-Secret` while always deleting client-sent copies. `src/lib/http.ts` is the only fetch wrapper (`request`, `ApiError` with `status`/`detail`/`fieldErrors`/`retryAfterSeconds`, `errorMessage`, `safeNext`); a 401 goes to `/login?expired=1&next=...` unless `redirectOn401: false` (login, signup, logout, the login page's `/me` probe). `src/lib/auth.ts`: `login`, `signup`, `logout`, `getMe`, `deleteAccount`. `src/proxy.ts` (Next 16 name for middleware) forwards `/api` (above, no cookie check) and checks that `session_token` or `__Host-session_token` exists on private paths, never touching `/login`, `/design` or `/privacy`; a stale cookie is the 401 flow's job (redirecting on it would loop). Never put tokens or user data in web storage. `?next=` always goes through `safeNext`. New fetches must go through `request`.
- Local P1 e2e and screenshots: `e2e-applications.cjs` covers the select, Change status (keyboard, skeleton observer, server-filled date); `e2e-interviews.cjs` has list-pane skeleton observers; `screens-statuses.cjs` shoots all nine statuses and three outcomes. Playwright needs a chromium build matching its version (`PW_CHROMIUM`): with Playwright 1.57 against Chrome 153 (build 1243 wants Playwright 1.63.0) `page.route` handlers never fire and `e2e-applications.cjs` stalls at the "dialog busy" status-failure step (no code regression; 75/75 passes with 1.63.0).
- Local F8 e2e: `frontend/scripts/e2e-agenda.cjs` (same `local-env.cjs`; Los Angeles browser, `ICS_OUT=<dir>` keeps the downloads for an external parser).
- Local F6 e2e and screenshots: `frontend/scripts/{e2e,screens}-interviews.cjs` (same `local-env.cjs`; the e2e runs LA and Auckland browser contexts and a "not found" flash observer). CI also runs `TZ=America/Los_Angeles npm test`.
- Local F5 e2e, seed and screenshots: `frontend/scripts/{e2e,seed,screens}-applications.cjs` (not in CI) share `local-env.cjs`, which starts the API on the `_test` database and `next dev` on free ports (an API port other than a busy :8000; `E2E_API_PORT=8100` keeps it off :8000 even when free; `E2E_WEB_PORT=3100` does the same for `next dev` and :3000), and on exit stops them, truncates the test database and prints that the dev database and a foreign :8000 process were untouched. Playwright via `NODE_PATH`; `PW_CHROMIUM` for a matching browser build.
- Local auth e2e and screenshots: `frontend/scripts/e2e-auth.cjs` and `screens-auth.cjs` use the same `local-env.cjs` (no manual server setup; `E2E_API_PORT=8100` keeps the API off :8000, `E2E_WEB_PORT=3100` keeps `next dev` off :3000; Playwright via `NODE_PATH`, `PW_CHROMIUM` for a matching browser build). Next 16 allows one `next dev` per checkout (lock in `frontend/.next/dev/`): if :3000 is a `next dev` from this checkout, the lock message "Another next dev server is already running." may appear in `frontend/.screenshots/logs/web.log` and the script then times out waiting for next dev (not reproduced); stop and ask rather than killing it.
- Screenshots: the `screens-*` scripts start `next dev` themselves through `local-env.cjs`, which sets `HIDE_DEV_INDICATOR`, so do not start `npm run dev` for them. Playwright runs are saved in `frontend/.screenshots/` (gitignored), never committed. For a manual screenshot outside the scripts, `HIDE_DEV_INDICATOR=1 npm run dev` hides the Next dev badge.
