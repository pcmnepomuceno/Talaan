# Talaan: Auth design decisions

Moved from CLAUDE.md on 2026-11-16. The every-session rules are repeated as one-liners in CLAUDE.md.

- **`BCRYPT_ROUNDS`** (`app/config.py`, default 12): cost for `hash_password` (read at call time) and for the login dummy hash (built once at startup), so they always match. `tests/conftest.py` sets 4; never lower it outside tests. **Must stay fixed after launch**: old hashes keep their cost, so a change reintroduces a timing gap between known and unknown emails (rehash-on-login is a possible future change; DECISIONS.md 2026-11-03).
- **Invite codes** (`app/auth/invites.py`, `app/admin.py`): signup requires `invite_code`. Format `TLN-XXXX-XXXX-XXXX` (12 Crockford base32 chars, 60 bits); input is normalized (non-ASCII rejected; strip, uppercase, drop dashes/whitespace, map O→0 and I/L→1, drop `TLN` only from 15-char input) then SHA-256 hashed. Single use, with expiry. Signup order: rate limit, non-consuming code check, duplicate email, then one transaction: insert user + atomic `UPDATE ... RETURNING` to consume (no row: roll back, same error). Every bad-code case is `400 {"detail": "Invalid or expired invite code."}`. No bypass flag; codes are created by the CLI or by an admin through the admin endpoints (next bullet). Tests make codes with `create_invite` in `tests/conftest.py`. Never log or return a plaintext code except the one-time CLI print and the one `POST /admin/invites` response. DECISIONS.md 2026-11-03 and 2026-11-21.
- **Admin invites** (`app/auth/admin_invites.py`, `require_admin` in `app/auth/dependencies.py`; DECISIONS.md 2026-11-21): `GET`, `POST` and `DELETE /api/v1/admin/invites`. Gate: `ADMIN_EMAILS` (comma separated, entries trimmed and lowercased, compared case-insensitively; unset or empty = nobody is an admin and the feature is off; production still starts, so `production_problems()` does not check it), compared with the session user's current email on every request, so an email change or a deleted account takes effect at once. No session is 401; a logged-in non-admin gets `404 {"detail": "Not Found"}`, FastAPI's own unknown-route body. Accepted leaks: (1) a malformed JSON body from a non-admin gets 422 before the dependency runs (a well-formed body is still 404); (2) anonymous callers get 401 where an unknown path gets 404, so the route can be found without logging in; (3) the `/admin` page keeps the app shell and returns 200 for a non-admin (the client draws "Page not found."); (4) Starlette answers other methods on these paths with 405 and an `Allow` header (for example `PUT /api/v1/admin/invites`) and 307-redirects a trailing slash (`/api/v1/admin/invites/`), to anyone, anonymous included, so the routes can be found (same reasoning as the anonymous 401). Create order: gate, rate limit, password, cap, insert. Password re-check: wrong is 403 `Incorrect password.` (not 401, like account deletion). Rate limits `ADMIN_INVITE_USER_*` and `ADMIN_INVITE_IP_*` (10 per user and 10 per IP per hour by default), committed before bcrypt and counted on every attempt, successful ones too. Cap: at most 50 unused, unexpired invites (409), counted under `pg_advisory_xact_lock` in the same transaction as the insert, so two creates at 49 cannot both pass. The code is in the 201 response only: it is never stored (only its SHA-256), never logged, and never in the list. The CLI is unchanged and not capped. POST and DELETE go through the Origin check like every write.
- **`ADMIN_EMAILS` must name an account that already exists.** Emails are not verified. An address listed in `ADMIN_EMAILS` that has no account yet could be claimed by anyone holding a valid invite: they sign up with that address and become admin. Remove the address from `ADMIN_EMAILS` before the admin account is deleted, otherwise anyone with an invite can register it again. This is an accepted limit until email verification exists (ROADMAP backlog).
- **Rate limits** (`app/auth/rate_limit.py`, Postgres): login per IP and per email, signup per IP; limits from env (`.env.example`). Client IP: `X-Talaan-Client-IP` when `PROXY_SECRET` is set and `X-Talaan-Proxy-Secret` matches (constant-time; sent by `frontend/src/proxy.ts`, which strips client copies), else the socket peer; `TRUST_PROXY=true` uses the right-most `X-Forwarded-For` instead of the socket. `TRUST_PROXY` is the only trust switch (run uvicorn with `--no-proxy-headers`). Limiter DB error returns 503.
- **Session cookie** (`app/auth/cookies.py`, the only place name and attributes live): HttpOnly, SameSite=Lax, Path=/, no Domain, Max-Age = `SESSION_LIFETIME`, Secure from `COOKIE_SECURE` (default true). Secure on: name `__Host-session_token`; off: `session_token`. Never `SameSite=None`. **With `COOKIE_SECURE=true` (the default) a plain-http client such as curl or Safari will not send the cookie; set `COOKIE_SECURE=false` in your local `.env`.** Existing local sessions stop working once because the cookie name changes. Tests force `COOKIE_SECURE=false`; cookie tests patch `config.COOKIE_SECURE` and read the raw `Set-Cookie`.
- **Origin check** (`app/security.py`, middleware inside `no_store`): POST/PUT/PATCH/DELETE get 403 if `Sec-Fetch-Site` is `cross-site`; `same-origin` passes without the list (Swagger at `/docs`); otherwise 403 if `Origin` is present and not in `ALLOWED_ORIGINS` (default `http://localhost:3000`, parsed by `config.parse_origins`: each entry `http(s)://host[:port]`, lowercased, default port dropped; `*` or a malformed entry fails startup). No Origin = allowed (non-browser). **Extension exception:** a write passes when its raw `Origin` is exactly one entry of `EXTENSION_ORIGINS` (`config.parse_extension_origins`; comma-separated `chrome-extension://<32 letters a-p>`, default empty, a malformed entry fails startup; no prefix or wildcard) and its raw `Sec-Fetch-Site` is exactly `none`; GETs are unchanged. Anything else with an extension Origin (trailing slash, uppercase, whitespace, another ID, a missing or different `Sec-Fetch-Site`) falls through to the rules above and gets 403. Why it is safe: `Origin` is a forbidden header, so a web page cannot forge it; another Web Store extension has a different ID; the session cookie is still required (401 without it); a non-browser client can forge `Origin` but has no ambient cookie, the same reasoning as the no-Origin rule. Residual risks, accepted until E3 tokens: (a) the ID comes from the public `key` in the manifest, so an unpacked copy that a user loads on purpose in developer mode and that reuses our key gets our ID; (b) GETs stay unchecked, so any extension with host permission on our host can read data with the cookie. No CORS middleware: the frontend proxies through Next.js. DECISIONS.md 2026-11-03 and 2026-11-22 (extension origin).
- **Account deletion** (`POST /api/v1/account/delete`, `app/users/router.py`): hard delete, password required (wrong = 403, not 401), rate limited per user and IP (`ACCOUNT_DELETE_*`), `FOR UPDATE` on the user row then one `DELETE`; FK cascades remove applications, interviews and sessions; `invite_codes.used_by_user_id` goes NULL (code stays used); the user's `login:email:<hash>` rate rows are deleted. Same email can re-signup only with a new invite code.
- **Sessions over JWT**: instant revocation (delete the row); no horizontal-scaling need.
- **Session lifetime 30 days**: `SESSION_LIFETIME` in `app/auth/router.py`, used
  for both `expires_at` and cookie `max_age` (must stay in sync). Rationale in DECISIONS.md.
- **Passwords**: at least 8 characters and at most 72 UTF-8 bytes (bcrypt limit)
  + upper/lower/digit/special; enforced on `UserCreate` only, not `UserLogin`.
- **Login failures return 401** (never 404/400), the same 401 for wrong password
  and unknown email. `/login` returns `{"detail": "Logged in"}` and sets the cookie
  (no token in the body).
- **`/logout` is idempotent**: always 204 and clears the cookie, even for a missing or
  invalid token; deletes the session row if one exists (DECISIONS.md).
- **`get_current_user`** (`app/dependencies.py`): reads cookie, loads Session,
  401 if missing; 401 + deletes row if expired; returns `User`. `GET /me` uses it.
- All Job Application/Interview routes must scope to the caller via
  `get_current_user` (`created_by`; interviews via their parent application).

- **Production mode** (`app/config.py`, `app/main.py`): `ENVIRONMENT=production` hides `/docs`, `/redoc`, `/openapi.json` and refuses to start unless `production_problems()` is empty (`COOKIE_SECURE` true, `BCRYPT_ROUNDS` >= 12, `PROXY_SECRET` set, `ALLOWED_ORIGINS` set to non-local https origins). Checked in `main.py` only, so the admin CLI and alembic need just `DATABASE_URL`.
